## Управление состоянием машины (кнопка STATE)
Круглая кнопка **STATE** (правый верхний угол, непосредственно слева от [волшебной палочки](#quick-start)) открывает диалог состояния машины — это полное сохранение и восстановление эмулируемого PDP-11, а не только процессора: регистры, память, каждое устройство ввода-вывода (консоль, терминалы, принтер, диски, лента и перфоратор/читатель перфоленты), бумага в телетайпе и LP11, содержимое экранов видеотерминалов (и VT52, и VT100) и даже картинка на векторном дисплее VT11. По сути это файл сохранения всей машины.

![Диалог состояния машины](assets/images/manual/dialog-state.png)

Диалог состояния машины с одним только что сохранённым состоянием.

- **Save state** — сохраняет машину ровно в том виде, в котором она сейчас, под автоматически созданным именем (дата и время). Аппаратная конфигурация входит в состояние: при восстановлении заново применяются тип консоли, пользовательские терминалы, принтер и дисплей VT11, а машина перезапускается им в соответствие.
- **Load** — восстанавливает выбранное состояние и перезапускает машину; сначала запрашивается подтверждение. Состояния, сохранённые более старыми версиями эмулятора, продолжают работать, а состояние, записанное **более новой** версией yaPDP, сначала спрашивает — Update to Latest / Open Anyway / Cancel. У кнопки **Load** есть выпадающее меню с пунктом **Load as shared state**: он повторяет подготовленное восстановление, которое показывает ссылка на состояние (снимок экрана, описание, шаги), — пункт доступен для состояний, у которых такое сопровождение есть.
- **Export** — сплит-кнопка с тремя опциями:
  - **Export** (основное действие) — скачивает выбранное состояние как бинарный файл `.state.zst`.
  - **Save as text file** — кодирует состояние в текстовый конверт (`.state.txt`), который можно передавать через каналы, не поддерживающие бинарные вложения.
  - **Copy text to clipboard** — копирует текстовый конверт прямо в системный буфер обмена.
- **Import** — сплит-кнопка с тремя опциями:
  - **Import** (основное действие) — открывает диалог выбора файла `.state.zst`, `.state` или `.state.txt` с диска.
  - **Import from clipboard** — читает текстовый конверт из буфера обмена и декодирует его.
  - **Import from URL** — запрашивает URL, загружает файл состояния по сети и импортирует его.
- **Share** — превратить состояние в файл, который можно передать другому человеку; что нужно, чтобы файл работал, — в подразделе «Передача состояния» ниже.
- **Rename / Delete** — упорядочить список или удалить состояния; счётчик рядом со списком показывает, сколько состояний сохранено.

Кнопка STATE доступна на тех же страницах, что и [REBOOT](#controls): **Panel**, **Console** (телетайп, VT52 или VT100), **TTY 1**, дисплей **VT11** и **Printer**. Расположена она в правом верхнем углу, рядом с [волшебной палочкой](#quick-start): обе относятся к уровню сессии и открывают диалог. Состояния хранятся в IndexedDB браузера и переживают перезагрузки и сессии.

### Передача состояния

Состояние — это файл целой машины, и ссылка может открыть его для другого человека. Форма ссылки —
`pdp11.html?state=<url>`, где `<url>` — место, где лежит файл: путь рядом с эмулятором
(`states/lander.state.zst` — так работают плитки в разделе [Игры](#guest-oses)) или полный `http(s)`-адрес
на вашем хостинге.

**Чтобы передать своё состояние:** откройте диалог состояния машины, выберите состояние и нажмите
**Share**. Диалог спросит слова, которые увидит получатель: **Title** (заголовок), **Description**
(описание), **Button label** (подпись на кнопке в сообщении, которое он прочитает перед получением
управления), **Screenshot** (снимок экрана) и **Run after restore** — команду, которая сама наберётся
в госте после возврата машины (например, `RUN SPCINV`).

Поле **Screenshot** принимает изображение, вставленное из буфера обмена (**Ctrl+V**), или выбранное
через диалог выбора файла. После прикрепления показывается превью; кнопка **Remove** убирает его.

![Диалог Share](assets/images/manual/dialog-share.png)

Диалог Share: заголовок, описание, снимок экрана, команда для выполнения после
восстановления и опция **Make state self-contained**.

Кнопка **Create Shareable State** — это сплит-кнопка с дополнительными опциями:
- **Copy text to clipboard** — копирует текстовый конверт состояния в буфер обмена.
- **Save as text file** — скачивает текстовый конверт как файл `.state.txt`.
- **Share via platform…** — передаёт состояние в системное окно «Поделиться» (Web Share API)
  файлом `.state.zst`, который принимающее приложение прикрепляет к сообщению. Если окно
  отклонило файл, диалог сообщает об этом прямо над кнопками, полный текстовый конверт
  попадает в буфер обмена, а пункт превращается в **Share state text…**: ещё один клик
  отправит конверт текстом сообщения — этот канал есть в любом настольном браузере.
  Состояние готовится, пока открыто меню, поэтому пункт остаётся недоступным, пока оно
  не готово.
- **Create GitHub Gist…** — открывает диалог Gist для создания **секретного** Gist на GitHub с
  состоянием машины. Потребуется GitHub Personal Access Token с областью `gist`.

  ![Диалог Gist](assets/images/manual/dialog-gist.png)

  Диалог Gist: введите токен GitHub и создайте ссылку для публикации.{.shot-caption}

  Диалог Gist предоставляет:
  - Поле ввода **PAT**, скрытое по умолчанию.
  - Кнопку **показать/скрыть** (&#9679; / #) для раскрытия или маскировки токена.
  - Кнопку **очистить сохранённый токен** для удаления токена из локального хранилища.
  - Кнопку **информация** (i) с инструкцией по созданию PAT.
  - Кнопку **Generate**, которая публикует состояние на GitHub и возвращает ссылку.
  - Сгенерированную ссылку можно **скопировать**, **проверить** в новой вкладке или **опубликовать**
    через платформу.

  При нажатии на кнопку **info** (i) открывается диалог **About GitHub Personal Access Token**,
  в котором объясняется модель безопасности: PAT используется только для создания Gist через
  GitHub API, никуда больше не отправляется и хранится в обфусцированном виде в localStorage.
  Диалог также содержит пошаговую инструкцию по созданию PAT с областью `gist`.

  ![Диалог About PAT](assets/images/manual/dialog-gist-about-pat.png)

  Диалог About PAT: политика безопасности и инструкция по созданию PAT.{.shot-caption}

Кнопка **Cancel** расположена отдельно от кнопок действий.

Флажок **Make state self-contained** делает файл переносимым: обычная передача ссылается на опубликованные образы этой сборки по версии и идентичности, а самодостаточное состояние несёт образы дисков внутри файла, поэтому восстанавливается на машине, где их нет вовсе. Файл становится больше на размер этих образов, а образ, байты которого прочитать не удалось, приводит к ошибке экспорта — обещать переносимость, которую нельзя выполнить, нельзя.

**Переносимость не наследуется автоматически новым снимком.** Если восстановить самодостаточное состояние, продолжить работу и затем сохранить новое состояние, новый снимок не унаследует встроенные образы дисков автоматически. Он может содержать только ссылку на исходный образ и дисковый overlay. Если это был пользовательский образ, которого больше нет после сброса или очистки хранилища, восстановить снимок с другим образом под тем же именем не получится: должно совпадать содержимое. Чтобы новое состояние можно было переносить независимо от исходного окружения, создайте для него отдельную самодостаточную публикацию (**Make state self-contained**).

Байты, которые уже загружены в этом браузере, находятся даже под другим именем файла — решает дайджест, а не имя. При сохранении состояния на диске, у которого нет опубликованной версии, появляется предупреждение о переносимости: такое состояние восстанавливается только здесь. Если восстановление всё же отклонено, в диалоге есть кнопка **Use my own copy of this disk…**: выбранный файл принимается только при совпадении дайджеста, после чего восстановление запускается само, а состояние не удаляется. Полные дайджесты лежат под **Technical details** вместе с **Copy details** для сообщения об ошибке.

Выложите этот файл туда, где он будет доступен по URL, и отправьте ссылку. На успех влияют две вещи:

- **Хостинг должен разрешать чтение файла с другого сайта** (заголовок `Access-Control-Allow-Origin`).
  Браузер не позволит этой странице прочитать файл на чужом хосте, который такого разрешения не даёт,
  и посетитель увидит сообщение «Shared state not restored» с указанием URL. Статические хостинги
  часто не отдают этот заголовок по умолчанию. Надёжнее всего **положить файл рядом с эмулятором** —
  на том же сайте, — ровно как отдаются состояния в каталоге `states/`.
- **Получателю нужны те же образы дисков — либо состояние должно нести их само.** Каждый образ
  идентифицируется SHA-256 от его распакованных байтов, и состояние может закреплять точную
  опубликованную версию, на которой было снято. Если образ отличается от того, на котором состояние
  снималось, восстановление **отклоняется**, а не применяется наполовину: машина с новой памятью и
  старым диском хуже, чем отсутствие восстановления. **Самодостаточному** состоянию от получателя
  не нужно ничего: образы едут внутри файла.

При восстановлении эмулятор, если образ ещё не загружен, скачивает закреплённую версию из реестра
образов, проверяет её дайджест и только потом трогает машину. Обычный **Export** встраивает то, что
может: образ, байты которого уже не загружены, остаётся внешней ссылкой, и уведомление предупреждает,
что экспортированное состояние от него зависит.

Если не выполнено любое из условий, посетителю показывается диалог с указанием URL, а в адресной
строке остаётся параметр `?state=`, чтобы было видно, что именно запрашивалось. Если ссылка не
может работать вовсе — состояние лежит там, откуда его не получить, — остаётся сам файл:
**Import** принимает любой файл `.state`, `.state.zst` или `.state.txt` с диска, без сервера и без CORS.

### Встраивание эмулятора

Эмулятор можно встроить в любую HTML-страницу через `<iframe>`. Это
делает его удобным для музейных экспонатов, образовательных сайтов и
онлайн-статей — посетитель взаимодействует с живой PDP-11, не покидая
ваш сайт.

**Базовая загрузка ОС**

```html
<iframe src="https://amesk.github.io/yaPDP/pdp11.html?boot=rk1"
        width="1024" height="768"
        allow="clipboard-read; clipboard-write"
        title="yaPDP PDP-11/70 Emulator">
</iframe>
```

Параметр `?boot=` запускает мастер быстрой загрузки для указанного
диска. Мастер набирает команду загрузки и, если учётные данные
известны, логин — посетитель сразу видит работающую операционную
систему.

**Загрузка состояния машины**

```html
<iframe src="https://amesk.github.io/yaPDP/pdp11.html?state=states/lunar-lander.state.zst"
        width="1024" height="768"
        allow="clipboard-read; clipboard-write"
        title="yaPDP PDP-11/70 Emulator">
</iframe>
```

Параметр `?state=` загружает сохранённое состояние машины. Файл
состояния должен быть доступен браузеру — см. обсуждение CORS выше.

**Использование GitHub Gist для обхода CORS**

Если вы не можете разместить файл состояния на том же хосте, что и
эмулятор, механизм GitHub Gist (см. [Передача состояния](#sharing-a-state))
решает проблему CORS: GitHub отдаёт «сырые» файлы Gist с правильным
заголовком `Access-Control-Allow-Origin`. Ссылка, сгенерированная
диалогом **Create GitHub Gist**, работает напрямую в iframe:

```html
<iframe src="https://amesk.github.io/yaPDP/pdp11.html?state=https://gist.githubusercontent.com/.../raw/.../demo.state.txt"
        width="1024" height="768"
        allow="clipboard-read; clipboard-write"
        title="yaPDP PDP-11/70 Emulator">
</iframe>
```

**Подготовленный экспонат для музея**

При создании публикуемого состояния поля **Title**, **Description**,
**Screenshot** и **Run after restore** (см. [Передача
состояния](#sharing-a-state) выше) позволяют подготовить
самодостаточный экспонат. Посетитель видит приветственное сообщение
с вашим описанием и снимком экрана до запуска машины; после нажатия
кнопки эмулятор загружается и автоматически набирает команду
восстановления. Никакой настройки сервера, никакого поиска дисков —
состояние несёт всё, кроме образов дисков, которые уже входят
в комплект эмулятора.

**Рекомендации для музеев и преподавателей**

- Используйте `?boot=` для быстрой демонстрации ОС — файл состояния
  не нужен.
- Используйте `?state=` с GitHub Gist для подготовленного экспоната,
  который переживёт смену хостинга.
- Укажите `allow="clipboard-read; clipboard-write"` в iframe, чтобы
  функции буфера обмена эмулятора (Import from clipboard, Copy text
  to clipboard) работали внутри встроенной страницы.
- Эмулятор адаптивен: на узких экранах он автоматически переключается
  в мобильный макет.

### Конфигурация и состояние

Состояние несёт собственную аппаратную конфигурацию, и при восстановлении применяется её профиль —
тип консоли, пользовательские терминалы, принтер LP11, дисплей VT11, ширины, скорость телетайпа,
масштаб, свечение, люминофор и фон. Есть одно исключение: две звуковые настройки (**Mute** и гул
машины) не трогаются никогда, потому что принадлежат человеку за клавиатурой, а не гостю.
Перезагрузка страницы происходит только если отличается **набор устройств**; всё остальное
применяется на лету.

Состояние, открытое по ссылке `?state=`, ничего не спрашивает — состояние и есть смысл ссылки. Ваша
собственная конфигурация запоминается до того, как её заменят, и после перезагрузки (или в диалоге
**Reboot** / **Bootstrap now!**) вам предлагают **Return my configuration**, что восстанавливает все
поля. Возврат вызывает перезагрузку только при другом наборе устройств, а отложенный Reboot
выполняется, как только страница вернётся.
