# Обмен состояниями машины

Состояния машины yaPDP --- это больше, чем файлы сохранения. С их
помощью можно передать другому человеку конкретный момент жизни
исторического компьютера: игру, готовую к запуску, программу,
остановленную в интересном месте, операционную систему посреди задачи
или демонстрацию периферийного устройства.

Вместо того чтобы просить человека установить эмулятор, найти нужные
образы дисков, настроить оборудование и повторить последовательность
команд загрузки, можно передать ему состояние машины, подготовленное
именно к тому моменту, который вы хотите показать. Добавьте название,
краткое описание, при необходимости снимок экрана и команду, которую
следует выполнить после восстановления. Получатель сможет исследовать ту
же исходную ситуацию и продолжить работу.

Таким образом, обмен состояниями становится формой сотрудничества. Можно
передавать друг другу прогресс в игре, воспроизводить необычное
поведение программы, готовить учебный материал или музейный экспонат,
показывать определённый момент работы компьютера. Состояние задаёт
исходную точку, а описание и необязательные пошаговые инструкции
объясняют, что в ней интересного и что можно сделать дальше.

## Какой способ обмена выбрать

Есть два практичных варианта. Выбирайте в зависимости от того,

состоянием.

## Вариант 1. Хранить коллекцию в публичном репозитории GitHub

Если вы собираетесь создавать и публиковать много состояний, публичный
репозиторий GitHub --- один из самых простых и недорогих вариантов. В
нём можно хранить файлы с понятными именами, README, снимки экрана и
пояснения. Состояния можно распределить по каталогам, а коллекцию
обновлять обычными средствами Git.

Например, репозиторий может выглядеть так:

``` text
yapdp-states/
├── README.md
├── games/
│   ├── space-invaders.state.zst
│   └── adventure.state.zst
├── operating-systems/
│   └── bsd-build.state.zst
└── peripherals/
    └── paper-tape-demo.state.zst
```

Это лишь пример организации: выберите структуру, которая подходит вашей
коллекции.

Для прямых ссылок через `?state=` файл состояния должен быть доступен по
URL, который браузер может загрузить. Удобный вариант для публичной
статической коллекции --- GitHub Pages. Проверяйте ссылку именно на
опубликованном сайте, а не исходите из предположения, что любой URL
GitHub отдаёт файл в подходящем виде.

### Требование CORS

Если открыть yaPDP по ссылке такого вида:

``` text
https://amesk.github.io/yaPDP/pdp11.html?state=https://example.org/states/space-invaders.state.zst
```

браузер должен загрузить состояние с `example.org`, пока страница
эмулятора работает на `amesk.github.io`. Это разные источники (origins),
поэтому сервер, на котором размещено состояние, должен разрешать такой
межсайтовый запрос с помощью заголовков CORS, обычно
`Access-Control-Allow-Origin`.

Это правило безопасности браузера, а не ограничение, специфичное для
yaPDP. Файл может нормально открываться или скачиваться в отдельной
вкладке, но при этом быть недоступным для JavaScript на другом сайте,
если сервер не разрешает CORS. Поэтому успешное открытие файла напрямую
ещё не доказывает, что ссылка `?state=` сработает.

Самый простой надёжный вариант --- размещать состояние на том же сайте,
что и эмулятор, как yaPDP делает со своими файлами в каталоге `states/`.
Если вы размещаете файлы в другом месте, убедитесь, что хостинг
разрешает межсайтовые запросы с сайта yaPDP. Не предполагайте, что
произвольный файловый хостинг, URL репозитория или облачное хранилище
настроены нужным образом.

Прямая ссылка на состояние также не включает все образы дисков,
используемые машиной. У получателя должны быть образы, на которые
ссылается состояние. Состояние, использующее стандартные образы из
комплекта yaPDP, проще передать другому человеку, чем состояние,
зависящее от собственного образа диска, который существует только в
вашем браузере.

## Вариант 2. Поделиться через GitHub Gist

GitHub Gist удобен, когда нужно поделиться одним состоянием, не создавая
и не поддерживая отдельный репозиторий. Gist предназначен для текстовых
фрагментов, тогда как файл `.state.zst` --- бинарный. yaPDP решает эту
проблему, преобразуя состояние в текстовый конверт.

Конверт начинается с маркера формата:

``` text
yapdp-text-envelope-v1
```

В следующих строках содержатся исходные байты `.state.zst`,
закодированные в Base64. Благодаря этому состояние можно передать через
текстовый сервис, например GitHub Gist. Base64 увеличивает размер
примерно на треть, поэтому текстовый конверт удобен для разового обмена,
но менее эффективен, чем хранение бинарных файлов в репозитории.

### Создание Gist в yaPDP

1.  Откройте диалог **Machine state** и выберите состояние, которым
    хотите поделиться.
2.  Выберите **Share** и заполните название и описание. Добавьте снимок
    экрана или краткую инструкцию, если они помогут объяснить ситуацию.
3.  Откройте меню рядом с кнопкой **Create Shareable State** и выберите
    **Create GitHub Gist**.
4.  Следуйте инструкциям диалога. Для создания Gist нужен GitHub
    Personal Access Token с разрешением `gist`.
5.  Создайте Gist и используйте полученную ссылку для обмена. Перед
    отправкой можно скопировать ссылку и проверить её.

Токен используется для создания Gist через GitHub API. Относитесь к нему
как к учётным данным: создавайте токен только с необходимым разрешением,
не вставляйте его в публичные документы и не передавайте вместе с
состоянием. Когда больше не хотите, чтобы yaPDP хранил токен локально,
удалите его из сохранённых данных. Актуальные сведения об обработке
токена смотрите в диалоге **About GitHub Personal Access Token** внутри
приложения.

Gist особенно удобен для быстрого обмена: отправьте ссылку в чат, задачу
или обсуждение, и получатель сможет получить текстовый конверт и
импортировать его в yaPDP. Не нужно настраивать отдельный хостинг только
ради одного подготовленного состояния.

## Вариант 3. Передать состояние напрямую

Если постоянная публичная ссылка не нужна, можно передать состояние
непосредственно:

-   **Export** скачивает бинарный файл `.state.zst`. Обычно это самый
    компактный вариант.
-   **Save as text file** создаёт текстовый конверт `.state.txt`,
    который можно передать через каналы, не принимающие бинарные
    вложения.
-   **Copy text to clipboard** копирует конверт в буфер обмена, чтобы
    вставить его в сообщение или текстовый сервис.
-   На стороне получателя используйте **Import** для выбора файла,
    **Import from clipboard** для вставки конверта или **Import from
    URL** для получения размещённого состояния.

При непосредственной передаче файла не нужен веб-сервер и не возникает
проблемы CORS. CORS имеет значение, когда браузерный эмулятор должен
загрузить состояние с другого сайта, например при переходе по ссылке
`?state=` или при импорте по URL.

## Что важно знать получателю

Общее состояние машины --- это воспроизводимая исходная точка, но не
обязательно самодостаточная копия всех данных, которые использует
компьютер.

-   Получателю нужны образы дисков, на которые ссылается состояние. Для
    переносимых примеров проще использовать стандартные образы,
    поставляемые вместе с yaPDP.
-   Состояние может содержать поясняющие метаданные и инструкции для
    управляемого восстановления. В названии и описании объясните, что
    увидит получатель; добавьте снимок экрана, если важен визуальный
    результат.
-   Если состояние показывает игру или эксперимент, объясните, что
    попробовать дальше. Хорошее состояние для обмена не только сокращает
    настройку, но и приглашает к исследованию.
-   Если прямая ссылка не восстанавливает машину, попробуйте
    импортировать файл состояния или текстовый конверт. Так можно
    отделить проблему хостинга или CORS от проблемы самого состояния.

## Краткие рекомендации

-   **Создаёте коллекцию?** Храните бинарные файлы `.state.zst` в
    публичном репозитории и публикуйте их через хостинг, который
    поддерживает необходимый межсайтовый доступ.
-   **Нужно быстро передать одно состояние?** Используйте интеграцию
    yaPDP с GitHub Gist.
-   **Передаёте состояние лично или через канал, блокирующий вложения?**
    Экспортируйте текстовый конверт и отправьте его как текст.
-   **Нужен самый компактный вариант?** Экспортируйте бинарный файл и
    передайте его напрямую.

Смысл не просто в передаче файла. Цель --- сделать конкретный момент в
исторической вычислительной среде доступным другому человеку, чтобы он
мог быстро попасть в него, понять, что происходит, и продолжить
исследование.
